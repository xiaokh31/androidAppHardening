# v0.2 SBOM 与漏洞扫描工具合同

## 1. 边界

本合同固定 V2-M3-01 实现的供应链工具入口和 V2-M4-01 执行的 fresh 安全审查。工具版本、schema、asset、数据库快照、网络边界和失败策略均不可由执行 Agent 重新选择。发布扫描不能使用 `latest`、浮动 tag、在线 fallback、平台各自下载的数据库或未记录的本机工具。

### 2.1 工具 component 权威来源闭包

`v02-toolchain-component-inventory.json` 中每个 component 都必须逐项引用下表唯一 `sourceProfile`；`sourceProfile` 与 vulnerability `coverageClass` 是两个独立必填字段。Gradle/Kotlin/AGP/CycloneDX plugin/Jazzer/JNA/apksig 及每个传递 Maven component仍属于 `osv-package`，但不能因此省略官方 release/Maven/source/advisory profile。`gradle/verification-metadata.xml` 与 frozen resolved graph 的并集是 Maven component 的封闭期望集合：每个 exact `group:name:version` 必须有独立 inventory record、独立 canonical coordinate、独立 artifact URL/size/hash closure和一个 profile；root project/profile 不能替其 transitive component背书。同一下载包内的 `java`、`javac`、`zipalign`、`aapt2`、`clang`、`ninja` 等子程序作为其 package component 的 member 记录，不得再用一个没有来源的泛化 `binary` 记录逃逸；Mbed TLS/TF-PSA-Crypto 使用 `native-vendor-advisory` profile，不得重复归类。

`locked-maven-published-artifact-v2` 的生成器及 validator 固定为 `tools/supply-chain-v02/locked-maven-published-artifact-v2.mjs`。V2-M0-02 必须把全部输入与结果写入 `v02-supply-chain-tools.json`，V2-M3-01/M4-01只复算，不能补录。先把 Gradle resolved graph 与 verification metadata按 UTF-8 `group:name:version` 排序取并集；每个 coordinate 的 `group/name/version` 必须是非空 NFC ASCII Maven token且不含 `/`、反斜杠、`..`、`%`、控制字符或 NUL，`groupPath` 只能把 `.` 逐字替换为 `/`。artifact filename只能来自 verification metadata的 exact name，且每个 coordinate 必须含 exact `name-version.pom`；从 POM 实际解析使用的 parent/BOM bytes 也进入闭包，不能仅记录 parent coordinate。不得因只解析 `.module`、平台未使用或当前图已不再使用而省略 metadata record。

首次 repository 选择只使用 `google-maven=https://dl.google.com/dl/android/maven2/`、`maven-central=https://repo.maven.apache.org/maven2/` 加 `groupPath/name/version/artifactName`。每个 coordinate 在两个仓库逐 artifact 获取并记录 status/MIME/size/hash：恰好一个仓库全部 HTTP 200 且匹配全部 verification hash，另一个全部 404，才唯一选择该仓库。部分命中、双命中、其他错误、size/hash不符或 repository混用均 `BLOCKED`。只有本选择算法规定的 404 negative observation 可接受；冻结后 official acquisition 仅访问 selected repository，任意 404/错误/漂移均 BLOCKED，不再选择。第三仓库例外严格限于上表 CycloneDX 3.4.1 implementation 与 marker 两个 exact coordinates，使用 `cyclonedx-plugin-portal`，不向其他 coordinate 扩散。HTTP body 必须实际读取并 hash，不能由 HEAD、缓存路径或文件名猜测来源。

CycloneDX implementation 三件只允许初始 HTTP 303 且 Location 精确等于 `https://plugins-artifacts.gradle.org/org.cyclonedx/cyclonedx-gradle-plugin/3.4.1/<该件既有SHA256>/<artifactName>`（此CDN使用含点的 `org.cyclonedx`，不得改成Maven groupPath），最终 HTTP 200、MIME `binary/octet-stream`。只锁并复验此一次固定 hop；中间响应只核验 status/Location，不对无正文的 hop要求 MIME/ETag。其他 Maven URL必须无重定向。marker 单URL固定 653 bytes、原SHA-256和 `application/xml`，其无ETag事实不得伪造：唯一 `revalidationPolicy=full-get-fixed-identity` 例外，每轮完整 GET并比对该三项，不能使用缓存；其余 final successful endpoints为 `etag-conditional`，沿用第2.2节 ETag规则。

新 profile 不构造 effective SCM：每个 exact POM 的 project URL、SCM URL/connection/developerConnection/tag 和 parent coordinate按 literal值记录为 `POM_DECLARED`；缺失值为 null，不把默认 HEAD、版本字符串、parent/root SCM或镜像当 immutable source commit。直接声明的 GitHub SCM只有全部非空 SCM URI能一致规范化到同一 owner/repo且无插值时，才产生 exact `https://api.github.com/repos/<owner>/<repo>/security-advisories?per_page=100`；该 URL 仍是 UNVERIFIED 声明，不能自报 vendor attribution/coverage PASS。

`mavenLock` 固定 `schemaVersion=2`、`identityKind=published-artifact-acquisition`、`securityPass=false`；包含 metadata path/size/SHA-256、resolved graph的 `path,sizeBytes,sha256,document`（size/hash绑定document的两空格/LF/末尾LF canonical bytes）、完整 `components`。每个 component 固定 `coordinate,group,name,version,sourceProfile,coverageClass,componentKind,repositoryId,pom,artifacts,repositoryObservations,pomDeclared,sourceCodeStatus,releaseInitialUrl,advisoryInitialUrl,advisoryStatus,securityReviewStatus`。named profile保留上表release/advisory；generic release URL为exact POM URL。`coverageClass=osv-package`；`componentKind=metadata|binary` 从 artifact extensions复算；`sourceCodeStatus=UNVERIFIED`、`securityReviewStatus=PENDING` 不可写 PASS。`pomDeclared` 的每个缺值理由为 `NOT_DECLARED`，有值为 `POM_DECLARED`。advisoryStatus仅 `UNVERIFIED|UNRESOLVED`：非空 URL必须前者、null必须后者。每个 artifact/observation 都有 `artifactName,artifactInitialUrl,initialStatus,artifactFinalUrl,status,sizeBytes,sha256,contentType,revalidationPolicy`，selected artifact必须 status 200，size来自完整HTTP body，hash精确匹配 verification metadata；404 observations记录实际负响应 size/hash/MIME。不得使用 guessed/source cache bytes回填 HTTP identity。

Maven MIME为本次已独立核验的封闭映射，而非兜底：Google JAR=`application/java-archive`、POM/module=`application/octet-stream`；Central JAR=`application/java-archive`、POM=`text/xml`、module=`application/vnd.org.gradle.module+json`；两仓库404=`text/html`。Plugin Portal仅使用上一段两项精确MIME。响应去参数/lowercase后必须等于该 endpoint锁定值；不得把任一 octet-stream值用于其他profile或文件类型。

所有源字段均由 exact POM bytes产生，所有 observations均由实际请求产生。任何 used parent/BOM不在 metadata集合时 BLOCKED，先由协调者补齐 checksum而不能跳过。canonical JSON固定两空格/LF/末尾LF与本文字段顺序；coordinate/artifact/observation按 UTF-8排序，缺失/额外/重复/重排/错误 profile/state/hash/MIME均失败。schema/validator必须拒绝将 lock `securityPass` 改为 true、sourceCodeStatus改为 VERIFIED或将 M0 acquisition完整误作 security PASS。

ADR 0021 只允许 M0-02 完整记录 acquisition身份，不免除源码、许可证、厂商来源、维护状态、advisory、reachability与漏洞审查。UNRESOLVED/UNVERIFIED/PENDING 是 freeze时事实，不是安全通过；V2-M4-01 缺任一必需证据仍 UNKNOWN/BLOCKED。后续审查结果写独立且绑定 exact lock hash 的证据对象，禁止覆盖 frozen lock。M0-02 合并后若需补/改 profile、endpoint或来源映射，必须新授权并重建 implementation freeze，再刷新 validation freeze；M3-01/M3-02不得补旧锁。不能保证当前固定依赖基线最终可发布。

表外 component、无法归入唯一 profile、一个 component 归入多个 profile、一个 transitive component只由root profile覆盖、用发行主页/搜索结果/CDN 镜像替代 endpoint、用 OSV 零发现替代 vendor review，或把 runner manifest 当作其全部 nested tool 的漏洞结论，均为 `UNKNOWN` 并直接 `BLOCKED`。`github-runner-image-v1` 必须把 official run 实际 `ImageOS`/`ImageVersion` 选择的唯一 manifest 及本次命令真正执行的 nested tool version逐项登记；未执行的 allowlist image 不作为本轮 component，但不能用来替换实际 image。

HTTP `Content-Type` 先去除参数、ASCII lowercase 后必须命中 profile 的封闭映射：所有 `api.github.com`、Gradle version、Node index、Ubuntu USN 与 MSRC JSON 为 `application/json`；Gradle/Node checksum 与 OSV `ecosystems.txt` 为 `text/plain`；OpenJDK、Node vulnerability 与 Android bulletin index/detail 为 `text/html`；Android repository XML 为 `application/xml` 或 `text/xml` 中由 machine lock逐 endpoint固定的唯一一个，不能二选一；OSV `all.zip` 为 `application/zip`；Maven/Plugin Portal仅使用前文封闭映射。实际 endpoint 的 lock 未固定唯一 MIME、响应 MIME 漂移、用扩展名猜测或用 `application/octet-stream` 兜底都 `BLOCKED`。

每个 endpoint 的 `paginationKind` 由本合同固定，worker 不得推断：所有 GitHub `releases/tags/*`、`commits/*` 与 `contents/*` 为 `single-json-object`，必须恰好一个 object且无 `Link rel=next`；所有 GitHub `security-advisories?per_page=100` 为 `github-link-array`，以 `Link rel=next` 连续到末页；Ubuntu USN 为 `offset-array`，首 URL/offset/limit/终止规则使用第 2.2 节；OpenJDK、Node vulnerability、Android bulletin与 MSRC为 `index-detail`，索引中符合固定时间范围的每个唯一 detail URL都必须获取；Gradle version 为 `single-json-object`，Node index为 `single-json-array`，Android repository为 `single-xml-index`，checksum为 `single-text`，OSV catalog为 `single-text-index`，每个 OSV DB ZIP为 `single-binary`。每个 recorded URL（包括 `index-detail` 发现的每个 detail URL、Maven/Plugin Portal artifact URL和所有分页 URL）都必须保存 ETag并在 run 前逐个条件复验；只复验首 URL、漏 detail、漏 transitive artifact或把 detail 当分页页均 `BLOCKED`。

Raw acquisition member path 只允许以下机器映射，禁止人工 slug：OSV catalog固定为 `acquisition/osv/catalog/`；每个 required ecosystem 的目录为 `acquisition/osv/ec-<sha256>/`，其中 `<sha256>` 是 catalog 中 exact case-sensitive ecosystem name UTF-8 bytes 的 64 位 lowercase hex SHA-256。工具目录为 `acquisition/tool/tc-<sha256>/<sourceProfile>/<endpointKind>-<sha256>/`。Maven component的第一个 hash preimage严格为 `sourceProfile NUL maven NUL group NUL name NUL version`；非 Maven工具严格为 `sourceProfile NUL binary NUL lockedName NUL lockedVersion NUL lockedPlatformOrEmpty`；第二个 hash preimage统一且严格为 `endpointKind NUL exactInitialEndpointUrl`。Native目录同理为 `acquisition/native/nc-<sha256>/<sourceProfile>/<endpointKind>-<sha256>/`，component hash preimage固定为 `sourceProfile NUL native NUL lockedName NUL lockedVersion NUL lockedCommit`，endpoint hash使用相同 `endpointKind NUL exactInitialEndpointUrl`。component preimage不得加入任何额外 release、候选或默认 URL字段；exact initial URL只能取该 profile/machine lock中与 `endpointKind`逐字对应的唯一字段。`endpointKind` 只能是封闭枚举 `release|artifact|checksum|advisory-index|advisory-detail|database-catalog|database-archive`；`index-detail` 每个 detail URL 使用独立 `advisory-detail-<sha256>` 目录，其 endpoint hash仍按该 detail exact URL计算，不得合并。NUL 为单字节 `0x00`，字符串不得 Unicode normalize；preimage中含 NUL、hash collision、同 URL映射到两 path、同 path映射到两 URL、缺/重复 endpoint-kind initial URL或任何非上述 prefix直接 `BLOCKED`。每个目录固定包含一个 `source-manifest.json` 和从 `page-000001` 连续编号的 headers/body 对；`single-*`/detail/artifact目录必须恰好只有 `page-000001`。

### 2.2 获取、分页、新鲜度和失败语义

本节及前文逐URL复验要求仅有第2.1节明确列出的三个303 hop与一个marker URL例外；不得扩大范围。

以上 release/advisory snapshot 与 Native vendor snapshot 只能由第 4 节同一个 Ubuntu acquisition job 获取，并统一执行以下机器合同：

1. 所有 `api.github.com` 请求固定请求头 `Accept: application/vnd.github+json`、`X-GitHub-Api-Version: 2022-11-28` 和本次 job 的只读 token；不得使用未版本化响应。首 URL 必须与上表逐字相同并执行该 endpoint 的 fixed `paginationKind`。仅 `github-link-array` 跟随响应 `Link` 中同 origin、同 repository、`rel="next"` 的绝对 URL，且 `per_page=100` 不得改变；`single-json-object` 必须无 next link。每个响应必须 HTTP 200、schema 正确、ID 唯一；缺页、环、跳页、类型错误、记录数不一致或 403/404/rate-limit 都 `BLOCKED`。
2. Ubuntu USN 从 `offset=0` 开始，每页固定 `limit=100`，仅令 `offset += 本页 notices 数`；直到响应的总数证明完整且最后一页少于 100。MSRC `updates` 是唯一索引，必须获取其全部唯一 document ID 和每个 exact CVRF document；Node vulnerability index 与 Android/OpenJDK advisory index 必须保存索引正文及其列出的、发布日期不晚于 acquisition 且不早于 locked component `versionPublishedAt` 的全部详情页。`single-*` endpoint只允许本合同指明者使用，必须满足对应单响应 schema和无 next link；不得由 worker写 `single-page` 自证完整。
3. 每次响应都记录 exact request URL、status、`Date`、`ETag`、`Last-Modified`（未提供时为 JSON `null`）、`Content-Type`、body size/SHA-256、`retrievedAt` 和 parser schema version。除第2.1节三个固定303 hop及单一marker的明确规则外，`ETag` 缺失、重复 URL 响应冲突、跨源 version/release date不一致或解析不到 locked version均直接 `BLOCKED`。所有列表按稳定 ID 排序后形成 source-specific manifest，并以 `path NUL size NUL sha256 LF` 计算 source tree SHA-256。
4. official security run 开始时间减每个 source 的 `retrievedAt` 必须在 `0..86400` 秒。run 前用原 `ETag` 对 acquisition manifest记录的每一个 URL（首 URL、分页、index detail、release/Maven artifact、checksum和binary）发送 `If-None-Match`：只接受 HTTP 304，或 HTTP 200 且 body size/SHA-256、`ETag` 与第一次完全相同。仅第2.1节三个固定303 hop重验status/Location、marker单URL完整GET重验固定身份；不能扩大该例外。出现更新、遗漏 recorded URL、未来时间、超过 24 小时、缺响应头或无法复验时 `BLOCKED`，不得选择旧 cache。
5. release endpoint、advisory endpoint、asset、snapshot 或 schema 任一不可用时，唯一结果是 `UNKNOWN/BLOCKED`。禁止 GitHub global advisory、NVD、OSV、搜索引擎、发行版镜像、Actions cache、本机 cache、另一 endpoint、另一版本或人工声明作为 fallback；补充来源只能作为 residual-risk 附件，不能使 gate 由 `BLOCKED` 变成 `PASS`。

V2-M3-01 冻结的 tool-review schema 必须对每个 component 保存 `toolComponentId`、`sourceProfile`、locked version/hash、release source manifest hash、advisory source manifest hash、support status、逐 finding version-range/reachability/disposition 和最终 `PASS|BLOCKED`。任一 finding 的适用范围无法机器判定、support status 未知、详情缺失、来源冲突、或没有逐 component 完整性证据，结果为 `UNKNOWN/BLOCKED`。

## 3. SBOM 生成、规范化与 schema

- `securityReviewV02` 在 Windows/Ubuntu 各生成 `bom-v0.2.0.raw.cdx.json`。固定 CycloneDX JSON `specVersion=1.6`、`includeBomSerialNumber=false`、`includeBuildSystem=false` 且不生成 XML；1.7 或其他格式不能替代 release SBOM。

- Canonicalizer通过 `V02_CYCLONEDX_CLI` 显式接收已预置 CLI 的路径，按第 2 节 exact平台 size/SHA-256 在执行前后核验；不自动下载、不使用 PATH同名程序、不允许替代 hash。raw/canonical均调用真实 pinned CLI，report记录实际退出码；缺工具或任一非零/异常/超时均不发布 canonical/report。
- Schema valid 不能替代集合完整性。独立 component validator 从 Gradle resolved graph、Native/launcher/component baseline 重建期望集合，拒绝缺项、额外项、重复 `bom-ref`、关系断裂、未知 license/source/hash 或 platform-only 漂移。

## 4. 唯一漏洞数据库快照

V2-M4-01 只允许一个有网络的 Ubuntu acquisition job：

## 5. 分层覆盖、权威来源与 severity

OSV-Scanner 2.5.1 offline mode 不支持 commit-level scanning，所以 scanner 的零发现只证明 `osv-package` 类，不能代表全部 component。official artifact raw member `reports/v02-component-coverage.json` 必须把产品 SBOM 与 toolchain inventory 的并集逐项且恰好一次分入以下固定枚举，并由 tracked `v02-security-artifact-manifest.json` 记录 path/role/platform/tuple/size/hash；它不得另行成为 tracked output。重复、遗漏、未知 class、模糊版本或未完成 class-specific evidence 均 `BLOCKED`：

- `osv-package`：具有 OSV 支持 ecosystem/name/version 或 purl 的第三方包，包括 Maven 依赖和可映射的 Gradle plugin/transitive。只允许使用上述 frozen offline scanner、同一数据库 snapshot 与 `--all-packages` coverage；package set 少一项、generic purl、unsupported ecosystem 或把 commit 当 version 都失败。
- `native-vendor-advisory`：只用于 Mbed TLS `4.1.1` commit `0a8fda272a5a0abef3b47c91bed37185d5a726b1` 与 bundled TF-PSA-Crypto `1.1.1`。同一个 Ubuntu acquisition job 必须 fresh 获取并封存 `Mbed-TLS/mbedtls-docs` 的 `security-advisories/` tree、`Mbed-TLS/mbedtls` 与 `Mbed-TLS/TF-PSA-Crypto` 的 official releases 和 repository security-advisories API 响应，记录 repository、resolved default-branch commit、request URL、ETag、GitHub API version、retrieved UTC、size/SHA-256 和 archive/tree hash。扫描开始距 retrieved UTC 必须在 `0..86400` 秒；缺源、分页不完整、HTTP/JSON/schema异常或来源相互冲突均为 `UNKNOWN`。
- `first-party-source`：只用于本仓库 exact freeze 从源码构建的 Host、Runtime、launcher 与 manifest；要求 source blob closure、编译 provenance、CodeQL/静态分析、Native sanitizers、独立安全复核和 reachability evidence 全部 PASS。此类不能用于外部库、预编译第三方二进制或 CI 工具。
- `tool-binary`：只用于不随产品分发的 CycloneDX CLI、OSV-Scanner、JDK/SDK/NDK/CMake/Node 等固定工具。要求工具机器锁、官方 release/security advisory snapshot、asset hash/provenance、版本支持状态和执行边界均复核；不存在 package mapping 不是 OSV 零发现，也不得转为 `first-party-source`。

冻结的 `evaluate-native-advisories-v02.mjs` 必须解析每个 Native vendor advisory 的 ID/CVE、affected version/range、fixed version/commit 和受影响 feature，按 SemVer/range判断 4.1.1/1.1.1，再由独立 reviewer 对每个匹配项提交 code-path reachability `REACHABLE|NOT_REACHABLE|UNKNOWN` 及 file/symbol/test evidence。无法机器判定 range、缺 fixed identity、commit-only/generic mapping、feature 状态不明或 reviewer evidence 缺失时为 `UNKNOWN` 并 `BLOCKED`。冻结的 tool review schema 对每个 `tool-binary` 采用同样的完整 source snapshot、finding 和 disposition规则；任何未覆盖才是 UNKNOWN，必须拒绝 false-zero，而不是宣称零漏洞。

- 只忽略 OSV 明确标记为 withdrawn 的记录；ignore/allowlist 必须是 tracked、具 ID/reason/owner/expiry 的显式安全决定，过期或无 owner 直接失败。
- 冻结的 `evaluate-osv-report.mjs` 从 raw OSV JSON 的 CVSS v3.0/v3.1 vector按 CVSS v3.1 base-score 公式独立复算并取同一漏洞的最高分：`9.0..10.0=Critical`、`7.0..8.9=High`、`4.0..6.9=Medium`、`0.1..3.9=Low`、`0.0=None`。
- 非 withdrawn 匹配项没有可解析 CVSS v3 vector、分数非有限/越界、alias 严重度冲突或 schema 未识别时分类为 `UNKNOWN` 并 `BLOCKED`；不得降为 Low/None。
- 任一未解决 Critical/High 或 UNKNOWN 阻塞。Medium 只有在记录 owner、影响、接受者 `/root` 和未过期 expiry 后才可继续；Low/None 进入 residual risk register。

## 6. 冻结与执行所有权

V2-M0-02 实现并冻结 CycloneDX plugin 配置、SBOM generation、`securityReviewV02` Gradle 入口、全部 transitive verification metadata 和工具锁，并把 bytes 纳入 implementation/toolchain manifests。V2-M3-01 只实现并独立复核 SBOM/component/coverage/schema validator、CVSS evaluator 和非执行 security workflow candidate，读取 V2-M0-02 exact lock，并把这些 validation bytes 纳入 `validationManifestSha256` 与 `releaseGateContractSha256`。V2-M4-01 只能在 exact candidate 上获取数据库、执行这些冻结入口并提交报告；它不得修改 tool version、validator、Gradle task、schema、workflow、severity 或 component 集合。需要修改时当前 tuple 失效，必须回到新的 freeze/candidate。
