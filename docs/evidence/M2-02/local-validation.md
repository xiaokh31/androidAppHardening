## 2026-08-07 authenticated Native transaction checkpoint

It rejects ZIP64/multi-disk/sentinel fields, ambiguous EOCD, duplicate or missing fixed assets, encryption, data descriptors, non-STORED methods, local/central mismatches, non-4-KiB data offsets, overlapping ranges, size violations and CRC-32 mismatches. It returns read-only byte ranges and performs no extraction or temporary-file write.
- Added exact 104-byte `NativeShareSlotV1` parsing and the ordered binding chain: slot SHA-256/ABI/build/key-slot, measured signer and Framework package digest, ADR 0006 KEK, ConfigV2 CEK envelope, streaming ADR 0008 manifest HMAC, authenticated config digest, and final signer/version/build/key-slot cross-checks. SHA-256 and segmented HMAC use the same serialized pinned PSA backend as AES-GCM/HKDF; no second crypto implementation or raw remote dependency was added.
- Added per-record key derivation and a fixed 65,536-byte authenticated-compressed buffer. Each chunk uses one-shot AES-256-GCM and is submitted to the record's single continuous zlib-wrapped inflater only after tag success. The loader separately classifies wrapper, dictionary, checksum, length, digest and trailing-stream failures, enforces the authenticated original length, and hashes the completed anonymous mapping.
- Added fixed-capacity transaction ownership for at most 64 anonymous mappings. Before commit, the transaction alone owns completed and partial DEX mappings; rollback clears and unmaps every mapping without allocating, continues after cleanup errors and reports cleanup failure separately without replacing the primary status. Commit atomically transfers all mappings to `PayloadHandle`, whose close path uses the same clear/unmap routine.
